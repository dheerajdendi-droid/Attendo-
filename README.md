# Attendo

Attendance & invoicing app for coaches and instructors running 1:1 or group sessions. React (Vite) client + Express/Postgres server.

Originally built for a dance studio, generalized into a reusable template: rate tiers, branding, and currency are all configurable through the app itself rather than hardcoded, so the same codebase can be cloned and stood up for a different trainer (this instance is configured for Kabir Badminton Services).

## Prerequisites

- Node.js 18+
- Docker Desktop (runs the local Postgres database)
- Git

## Run it locally

1. **Start the database**
   ```
   npm run db:up
   ```
   This starts a Postgres container (`docker-compose.yml`) on `localhost:5432`.

2. **Install dependencies** (once, or after pulling dependency changes)
   ```
   npm install
   ```
   This is an npm workspaces repo (`client` + `server`), so one install at the root covers both.

3. **Environment files**
   ```
   cp .env.example .env
   cp client/.env.example client/.env
   ```
   `.env` needs `DATABASE_URL`/`SESSION_SECRET` at minimum. Social sign-in (`OWNER_EMAIL`, `GOOGLE_CLIENT_ID`, `FACEBOOK_APP_ID`/`FACEBOOK_APP_SECRET`, and the matching `VITE_*` copies in `client/.env`) is optional — leave them blank and the app falls back to PIN-only login.

4. **Run migrations**
   ```
   npm run migrate
   ```

5. **Start the app** (two terminals/processes)
   ```
   npm run dev:server   # Express API on http://localhost:4000
   npm run dev:client   # Vite dev server on http://localhost:5173
   ```
   Open **http://localhost:5173** — the client dev server proxies `/api` requests to the server on port 4000 (see `client/vite.config.js`).

6. **First run**: the app has no accounts yet — it'll prompt you to set a 4–6 digit PIN on first load (`POST /api/auth/setup`), or sign in with Google/Facebook if those are configured. Two default rate tiers ("Group Session", "1:1 Private") are seeded by the migration — rename/reprice/add more from the Students tab.

### Other useful scripts (run from repo root)

| Command | What it does |
|---|---|
| `npm run db:down` | Stop the local Postgres container |
| `npm test` | Full test suite (server API tests + client unit tests) — see below |
| `npm run backup` | Dumps all tables to a timestamped JSON file in `backups/` (gitignored — contains real student/client data) |
| `npm run restore` | Restores from a backup file |
| `npm run build` | Builds the client for production (`client/dist`) |

### Testing

```
npm test          # everything
npm run test:api  # server API tests only (spins up/migrates an isolated test DB first)
npm run test:unit # client unit tests only
```

Requires Docker running and `.env.test` at the repo root (gitignored) pointing at the isolated test database — see `.env.example` for the shape.

## Customizing for a new trainer

Everything below is settings-driven — no code changes needed for a fresh clone:

- **Rate tiers** — Students page → rates card. Add/rename/reprice as many tiers as needed (e.g. "Group", "1:1 Private", "Semi-Private").
- **Studio name & currency symbol** — Students page → branding card.
- **Owner login** — set `OWNER_EMAIL` to gate Google/Facebook sign-in to one account; PIN login always works regardless.

A few things are still manual per-clone edits (cosmetic, install-prompt-only, not worth wiring through settings):
- `client/index.html` `<title>`
- `client/vite.config.js` PWA manifest (`name`, `short_name`, `description`, `theme_color`)
- `render.yaml` service/database names

## Deploying to production

This repo is set up as a **Render Blueprint** (`render.yaml`) — it provisions a managed Postgres database and a Node web service together from one file.

1. **Push this repo to GitHub** (Render deploys from a connected git provider, not local files).

2. **In the Render dashboard**: New → Blueprint → connect the GitHub repo. Render reads `render.yaml` and provisions:
   - A free Postgres database (`attendo-db`)
   - A free Node web service (`attendo`) with:
     - Build: `npm install && npm run build`
     - Start: `npm run migrate && npm start`
   - `DATABASE_URL` is wired automatically from the provisioned database.
   - `SESSION_SECRET` is auto-generated by Render.
   - `NODE_ENV=production` is set automatically.
   - `OWNER_EMAIL`, `GOOGLE_CLIENT_ID`, `FACEBOOK_APP_ID`, `FACEBOOK_APP_SECRET`, `VITE_GOOGLE_CLIENT_ID`, `VITE_FACEBOOK_APP_ID` are marked `sync: false` — enter these manually in the Render dashboard if you want social sign-in; leave blank for PIN-only.

3. **Deploy.** Render builds and starts the service; your first visit to the live URL will prompt for PIN setup (or social sign-in) against a fresh database.

4. **Subsequent deploys**: pushing to the connected branch on GitHub auto-deploys, running the same build/start commands, including migrations.

## Setting up social sign-in (optional)

- **Google**: create an OAuth 2.0 Client ID (Web application) in the [Google Cloud Console](https://console.cloud.google.com/apis/credentials), add your deployed URL to "Authorized JavaScript origins". Set `GOOGLE_CLIENT_ID` (server) and `VITE_GOOGLE_CLIENT_ID` (client) to the same value.
- **Facebook**: create an app at [developers.facebook.com](https://developers.facebook.com/), add the Facebook Login product, add your deployed URL to "Valid OAuth Redirect URIs" and "App Domains". Set `FACEBOOK_APP_ID` + `VITE_FACEBOOK_APP_ID` (same value) and `FACEBOOK_APP_SECRET` (server only). The app can stay in Development mode — only added testers can log in — since this is single-owner login, not public.
- Either way, set `OWNER_EMAIL` to the Google/Facebook account that should be allowed in.
